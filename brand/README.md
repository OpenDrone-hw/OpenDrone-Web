# Brand assets

The logo files are not in this repo. They live in
**[OpenDrone-Brand](https://github.com/OpenDrone-hw/OpenDrone-Brand)**, which is
the only place they are generated and the only place to take them from. This
folder used to hold a second copy of that package; it was deleted because two
copies of a logo drift.

Writing about OpenDrone, reviewing a board, listing us as a supplier? Take what
you need from OpenDrone-Brand, and read the usage rules there before you do.

## What this repo does hold

Site plumbing only, generated by `scripts/gen-site-assets.py`:

| File | Purpose |
|---|---|
| `app/assets/favicon.svg` | the mark, source for every icon below |
| `public/icon-192.png`, `public/icon-512.png` | PWA icons, from `manifest.json` |
| `public/apple-touch-icon.png` | iOS home screen |
| `public/og-image.svg` + `.png` | 1200x630 social card |
| `public/opendrone-wordmark.svg` | the traced logotype, also the source artwork |
| `public/opendrone-wordmark-{400,1200,2400}.png` | raster renditions |

Regenerate with `python3 scripts/gen-site-assets.py`. It is deterministic: the
same inputs give byte-identical output, so a rerun that changes nothing produces
an empty diff.

## Colour

**Do not look for the values here.** They live in
[`tokens.json`](https://github.com/OpenDrone-hw/OpenDrone-Brand/blob/main/tokens.json)
in OpenDrone-Brand, which is the source of truth for screen and physical colour
alike, along with the reasoning, the contrast numbers, the retired hexes and the
Pantone master. This file used to restate all of it, which is exactly how six
different golds ended up in this repo.

What is true *here*, and nowhere else, is how the site consumes it:

`#ffb700` is the only gold literal in `app/styles/app.css`. Every other gold
token is mixed from it, so there is nothing to keep in sync:

```css
--color-gold:            #ffb700;
--color-gold-hover:      color-mix(in oklab, var(--color-gold) 82%, white);
--color-gold-soft:       color-mix(in srgb, var(--color-gold) 12%, transparent);
--color-gold-bright:     var(--color-gold);   /* alias, prefer --color-gold */
--color-gold-fill:       var(--color-gold);
--color-gold-fill-hover: var(--color-gold-hover);
--color-focus:           var(--color-gold);   /* html.light: var(--color-text) */
```

Two site-specific consequences of one gold, both deliberate:

- **Gold is 1.62:1 on the light surface.** Fine for the mark and the wordmark,
  which are exempt from contrast rules. Gold chips and eyebrows on light sit at
  roughly that too, which is a deliberate brand accent, not an oversight
  Anything a user has to *read* rather than recognise uses
  `--color-text` or `--color-text-muted`.
- **Focus rings never use gold.** WCAG 1.4.11 wants 3:1 and gives focus
  indicators no logo exemption, so `--color-focus` is ink on light.

### Email

Email cannot use CSS variables, so the gold is inlined as a literal in
`app/lib/support/email.ts`, `scripts/launch-blast.mjs` and
`scripts/newsletter-template.html`. Those are the only places a gold hex may
appear outside the stylesheet. Buttons are fine,
dark ink on a gold fill. Gold link text in email is 1.75:1 on a white client,
which is a known cost of one gold rather than an oversight.
